# ✅ Skill 验收流水线（skill-acceptance） ![版本](https://img.shields.io/badge/版本-v1.5.2-blue)

> 一句话验收一个 AI skill：场景枚举查入口覆盖 → 路径模拟查流程断链 → 统一验收报告。

---

## 这是什么（30 秒看懂）

你的 skill「看起来很完整但实际用不了」？这个验收流水线把两套互补的方法论串成一条命令：

1. **结构体检**（静态清单）——孤儿 references、断裂引用、文档脚本割裂、触发词漂移、8g 跨文件判据对账
2. **场景枚举**（横向轴）——穷举「谁、说什么话、要什么结果」，查整类用户没被覆盖
3. **路径模拟**（纵向轴）——沿真实指令走到底，查流程断链
4. **统一报告**——问题清单（阻断/一般/建议）→ 等你确认 → 修复后重走

## 怎么用

对你的 AI 助手说一句话：

> 「验收 XX skill」

输出：范围声明（增量|全量）+ 覆盖声明 + 问题清单（阻断/一般/建议）+ 走查轨迹 + 误报记录 + 体量账（字符口径）；交付后登记台账（status/coverage/scope/size/issues/fixed/note）。

## 验收流程

```
Phase 0 定界：被测 skill 路径 + 类型（流程类/知识类）+ 范围（增量/全量——增量不豁免 8g/#7 必走项）+ 所有权（自己/第三方）
   ↓
Phase 1 结构体检（skill-health-audit 体检清单 + 自动化脚本，含 8g 全量判据对账）
   ↓
Phase 2 场景枚举（path-simulation 步骤 0：五维矩阵）
   ↓
Phase 3 路径模拟（path-simulation 步骤 1 至末尾：标准/异常/跨文件 #7 判据配对）
   ↓
Phase 4 统一报告 🔴 报告先于修复——等确认才动手
   ↓
Phase 5 修复 + 负例/回归重走
```

## 🔴 一条不可妥协纪律

**验收发现的问题，必须先出报告、等使用者确认后才修。** 对每一轮新发现都生效——「同会话拍板过大方向」「改动看起来机械」都不是跳过的理由。实测违反的后果：修复未经验证、格式错位、返工。

## 适合 / 不适合

**适合**：
- ✅ 新建 skill 的交付前验收
- ✅ **开发方案 / 实施计划（plan）的验收**——plan 是流程类文档：结构体检核它引用的源文件与声称，场景枚举查决策点/边界场景漏没漏，路径模拟走「照着方案执行」查里程碑断链（实测：一份插件开发 plan 走查抓出 2 个阻断级会话归属错位 + 4 个一般问题）
- ✅ 多轮迭代后的 skill（孤儿/残留/触发词漂移是高频病）
- ✅ 架构改造后（旧口径残留对账）
- ✅ 开源发布前（结构不健康谈开源是空中楼阁）

**不适合**：
- ❌ 纯知识类文档（无执行步骤）
- ❌ 发布到 GitHub 的流程本身（另用发布清单，本 skill 只管验收）
